# dsh-workplan 1.12.0 — 低风险补丁 rebase、理解与分配护栏、分步进度折叠

发布日期：2026-11-02

1.12.0 把四批改动收敛到同一条发布链上：**T11 的 15 个低风险缺陷**重新 rebase 到 1.11.1 之上、**任务理解与部门分配**补上可执行护栏、**分步进度**改为默认收起、点击展开，以及**默认自动派发 + 验收稳定编号（U-16）**收口。全量回归 **459 / 459 通过、0 失败**。

## 亮点

### 1. 15 个低风险缺陷，44 个 hunk 全部有回归

- 45 个源 hunk：31 个可直用、11 个按新上下文改写、3 个废弃（D-15 / D-17 已被 1.11.0 以不同实现修好，强打会回退）；最终 44 个 patch hunk、7 个文件。
- 每个 hunk 至少 1 条可执行用例，新增 52 条；在未打补丁的基线上同批对照，**43 / 44 个 hunk 为 fail-before**。唯一例外（hunk 33 / D-19）在基线本就拒绝环，已标注为「补独立基线」，不冒充判别力。
- 覆盖缺陷：`D-04 / D-07 / D-08 / D-09 / D-10 / D-11 / D-15 / D-17 / D-19 / D-21 / D-28 / D-30 / D-31 / D-35 / D-45`。

### 2. 任务理解与部门分配：从「只有枚举」到「有锚点、有理由、能拒绝」

- **只读锚点**：用户原文 + `sha256` 存进计划；哈希不一致即降级，不带着被改写的「原要求」通过校验。
- **要素抽取**：版本号、日期、编号、路径、数量、数值边界、指代、矛盾；无上下文的裸「它」判 `needs-context`，不猜。
- **部门能力目录**：12 个部门各有职责、典型产物、关键词；分配输出 `fit / weak / mismatch`，受保护部门还会检查「原任务从未涉及该领域」的侵入。
- **偏离自检**：硬要素缺失、交付动作缺失、部门矛盾会被 `DEVIATION:` / `CLARIFY:` / `CONTEXT:` 阻断并走既有重试，不派发。
- **回退开关**：`DSH_WORKPLAN_CONTEXT_GUARD=off` 时审计照常运行、只告警不阻断。

真实历史计划回放：41 个子任务 `fit 41/41`、`mismatch 0`；一个含 7 个硬要素的样本 0 丢失。这只证明「旧计划不被误伤」，**不证明真实模型对新任务的理解质量**。

### 3. 自动化闭环：预算到点不再丢状态

修掉 4 组「看起来在跑、实际丢状态」的缺陷：预算到点不再把 `escalated` / `instructed` / `replanned` 重置为 `pending`；`replanned` 旧行不再被当作待续跑；`HAS_BLOCKED` 不再被 `NOTHING_PENDING` 抢先；修正 3 处「自动续跑默认关闭」的错误文案与 1 处不存在的强制派发注释。

### 4. 分步进度：默认收起，点一下展开

- 每行默认收起，只显示状态点、第 N 步名称、进度条、done/total、状态词；
- 点击行或键盘 Enter / Space 展开该步摘要（目标、检查点、子任务状态），再次触发收起；
- `aria-expanded` / `aria-controls` 与 `hidden` 面板同步，点击不冒泡到外层卡片；
- 展开状态按会话持久化（`dsh-workplan:planrow-open:v1:<sessionId>`），刷新后恢复；localStorage 不可用时降级为纯内存。

### 5. 默认自动派发与验收编号（U-16）

- **自动派发**：计划落地后立即以 async 方式调用 `dispatchPlan`，结果仍由 `finishRound` 写回；计划消息改为「已自动派发，不要重复调用 dispatch」。plan 模式不自动派发；`autoDispatch:false` 或 `DSH_WORKPLAN_AUTO_DISPATCH=0` 可回到 plan-first。预算、取消、幂等、交付门禁与自动续跑保留。
- **验收编号**：子提示词把计划验收编号为 A1…An，证据必须按编号对号入座；`acceptanceCoverage` 去掉反向包含，计划要求「通过登录测试与越权测试」时，只写「通过登录测试」不再算覆盖。复跑探针 `BYPASS=BLOCKED`。
