# dsh-workplan 3.1.9

## 3.1.9 — 2026-11-22（把重复送进模型的同一份内容拿掉）

这一版不新增模型调用，也不改变任务怎么派、怎么验收；它只做一件事：**同一份信息只让模型看一次**。
下面每个数字都来自本机真实会话或源码构建后的实测，不是估算口号。

### 一句话结论

| 场景 | 旧版每步要付 | 3.1.9 每步要付 | 省下 |
|---|---:|---:|---:|
| 主 Agent 看到计划消息后的每一步 | 计划全文 23,071 字符 | 5,262 字符 | 17,809（-77%） |
| 主 Agent 的 workplan 工具说明书 | 26,631 字符（14 件） | 15,046 字符（11 件） | 11,585（-43%） |
| 部门负责人/专家 phase-1 五步说明 | 3,583 字符 | 1,611 字符 | 1,972（-55%） |
| 负责人任务书的依赖结果块 | 实测约 6.7KB | 约 2.6KB | 约 4KB |

主会话每步合计少付约 **29.4K 字符**的常驻内容（计划 17,809 + 工具面 11,585），这是本轮最大的两块。

### 1. 计划不再整包塞进聊天消息

旧版计划消息长这样：开头一行摘要 + 用户任务 + 23KB 的 `{"plan": ...}` JSON。它一旦进入会话，
之后每一步都会重新送给模型。

现在：
- 完整计划（含方法、输入、输出、验收、质量、理解审计等）原样放进消息的 `source.durable`，
  回放、看板、刷新恢复都能读；
- 聊天里只显示人看得懂的骨架：标题、全局任务、交付物、主要矛盾、每个阶段、每个子任务的
  目标 / 依赖 / 验收 / 质量；
- 用户刚才输入的任务原文仍然逐字保留（用户要求 1 不变）；
- 旧会话没有 durable 时，读端自动回退旧文本 marker，不需要迁移。

真实样本 `wp-d3448f95`（5 阶段 / 14 子任务）从 **23,071 → 5,262 字符**。

### 2. 根会话不再为「永远调不通」的工具付说明书

这三个工具在根会话调用必然被 runtime 拒绝：

- `dsh_workplan_delegate`：需要 `parentSession`，根会话没有；
- `dsh_workplan_escalate`：需要已登记 childId 或第三层叶子上下文；
- `dsh_workplan_verify`：需要 `parentSession` 反查父计划。

旧版仍把三份说明书注入根会话。现在只在「声明面」隐藏，权限硬校验不动：
根会话 14→11 件工具；按运行时 `request/header` 实测，注入模型的工具说明从 **26,631 → 15,046 字符**（-11,585，约 -43%）。负责人/专家的工具面不变。

### 3. 负责人任务书不再把依赖结果和兄弟简报各写一遍

旧版：
- 「依赖子任务的已知结果」把上游完整汇报（常带 `WORKPLAN_EVIDENCE` JSON）整段贴进来；
- 「兄弟部门进展」又把同一批依赖项列一遍。

现在：
- 依赖摘要去掉证据块、压平空白、每条最多 1,200 字；产物路径保留，需要原文可去读；
- 兄弟简报排除已在上方出现的依赖 ID；若没有其他兄弟，保留一句说明，块不消失。

### 4. phase-1 不再重讲前三步

phase-0 已完成并登记第 1/2/3 步；phase-1 任务书却仍带完整 3,583 字符五步说明，其中大部分在讲
前三步怎么做。现在 phase-1 用精简版（1,611 字符），只讲第四步执行/验证、复盘、第五步 JSON 交付、
开工/结算闸和全部字数上下限；phase-0、主 Agent、旧计划路径继续用完整版。

### 5. 修掉的「局部与整体互相矛盾」

- 工具声明说「能派发/能请示/能核验」，execute 却必然拒绝——已统一；
- 计划消息还是整包 JSON，而结果/取消/重规划早已迁到 durable——已统一；
- 依赖结果与兄弟简报重复——已去重；
- 任务书一边说「前三步已完成不要重做」，一边用 3.6KB 重讲前三步——已按阶段分流。

### 怎么确认生效

重启 DSH 后，在会话里调用 `dsh_workplan_status`，返回的版本应为 `v3.1.9`。
本轮没有新增模型调用，也不需要改任何配置。
