## 1. 结论（先看这一行）

**34 项测量中 33 项通过 WCAG AA，1 项未达标**：浅色主题下 **Chart.js 画布内的图例文字与坐标轴刻度**实测 **1.14:1**（阈值 4.5:1）。
根因是**代码缺陷**（取 token 的 DOM 节点用错），不是配色意图问题：`src/client.ts:1425` 用 `getComputedStyle(document.documentElement)` 读 `--dsw-alias-label-primary`，而该 token 在宿主 CSS 中只定义在 **`body`** 上、从未定义在 `html` 上，因此永远取到空串，回退为硬编码 `#e2e8f0`。深色主题下这颗灰恰好够亮（12.72:1，通过），浅色主题下几乎不可见。

**"一目了然"层面的判定**：面板自身的 DOM 文字（组标题、计数徽章、摘要、图例、卡片小标题）全部达标且余量充足（最低 5.15:1）；但**柱状图卡片的图例与刻度在浅色主题下等于不可读**，这一张卡片目前不满足"一目了然"。

## 2. 方法与可信度边界（务必先读）

### 2.1 为什么不是浏览器 `getComputedStyle` 的读数

本机**没有可用的无头浏览器**：`/Applications` 只有 Safari，无 Chrome/Chromium/Edge；无 `playwright`/`puppeteer`/`electron` npm 包；`~/Library/Caches/ms-playwright` 为空；`safaridriver` 需 `--enable`（需审批，本会话审批被自动拒绝）。页面又受签名 cookie 保护（`GET /` → 401），本会话拿不到会话 cookie。

因此本次采用**解析式实测**：直接解析"服务端实际派发的那份 CSS 与 token 定义"，再用 WCAG 公式计算。这不是"读源码猜效果"，因为：

| 证据 | 实测值 |
|---|---|
| 派发 `client.js` 字节数 / SHA-256 | 111,815 B / `60de4b65…946464f`，与本地构建**逐行相同** |
| 派发 `/assets/index-BXV-oxvX.js` SHA-256 | `0f3fc6b857e4f8bd…` == 本地安装包同名文件 |
| 主题 token 来源 | `@deepseek-ai/dsh-client-ui-theme/lib/client.js` 内 `design_platform_css_default` 字面量，与运行进程同一份 npx 安装 |

### 2.2 半透明背景的"有效合成色"怎么取值

按 **CSS Compositing and Blending Level 1** 的 source-over 规则，在 **sRGB 非线性通道**逐通道计算：`C_out = C_fg·α + C_bg·(1−α)`。浏览器对 sRGB 颜色默认就在该空间合成（不做线性化），所以手算与浏览器结果一致——这一点**未在真实浏览器中复核**（见 §6 未验证项）。

叠加链（每层都是"上层半透明色 × 下层已合成的有效色"）：

| 层 | 浅色主题 | 深色主题 |
|---|---|---|
| 面板底 `.dsh-wp` | `--dsw-alias-bg-base` = `#ffffff`（不透明） | `#151517`（不透明） |
| 组卡 `.dsh-wp-group` | `rgba(148,163,184,.05)` 叠面板 → **`#fafafb`** | → **`#1b1c1f`** |
| 图表卡 `.dsh-wp-chart-card` | 渐变最不透明端 `rgba(148,163,184,.10)` 叠面板 → **`#f4f6f8`** | → **`#222327`** |
| 计数徽章（进行中） | `rgba(249,115,22,.14)` 叠组卡 → **`#fae7db`** | → **`#3a281e`** |
| 计数徽章（已完成） | `rgba(14,165,233,.14)` 叠组卡 → **`#d9eef9`** | → **`#192f3b`** |
| 需关注徽标 | `rgba(239,68,68,.12)` 叠组卡 → **`#f8e5e5`** | → **`#352123`** |
| 组头按钮 hover | `rgba(148,163,184,.10)` 叠组卡 → **`#eff2f5`** | → **`#272a2e`** |

两点必须说明：

1. **`--dsw-alias-bg-elevated` 与 `--dsw-alias-line-1` 在宿主主题包里各自 0 处定义**（实测 `grep -c` 均为 0）。所以组卡底色**不是**"抬升表面"，而是上面那个 5% 板岩灰回退值；1px 描边同样是 `.22` 的回退值。描边不参与文字对比度（只压在边线上，不压字面）。
2. 图表卡取**渐变最不透明端**（顶部 `.10`）作背景，是**最不利**取法；若取底部 `.02`，对比度只会更高。

### 2.3 阈值

- 正文：**4.5:1**（WCAG 2.x AA）。本次被测字号最大 15px/700、13px/650，**均未达到"大字"门槛**（≥24px，或 ≥18.66px 且 ≥700），所以一律按 4.5:1 判定，**没有任何元素享受 3:1 放宽**。
- 非文本图形（完成度环弧）：**3:1**（WCAG 1.4.11）。

## 4. 字号实测（是否触发"大字"放宽）

| 元素 | 实测字号/字重 | 是否属"大字" |
|---|---|---|
| 组标题 | 15px / 700 | 否（<18.66px） |
