# dsh-workplan 3.1.8

## 3.1.8 — 2026-11-22（并发位自锁治本）

### 这次修的是什么

复杂部门任务在宿主默认并发设置下会「长时间无响应」：部门负责人派发 8 名以上专家时，
第 8 个之后的成员抢不到并发位；每位专家开工登记（`self_effort`）又要新起一个执行
会话，而旧会话的并发位必须先结束回合才释放——工具调用在等空位、回合在等工具返回，
形成自锁，最长约 20 分钟才超时报错。默认 8 个并发位、插件又要求至少 8 名专家，
所以这是必然复现，不是偶发。

### 3.1.8 怎么修

1. 开工登记（`self_effort`）在并发位已满时立即返回，不再占住负责人的工具调用；
   回合结束后由后台任务自动把该专家接续到正式执行会话（phase-1）。
2. 派发先把全部专家登记进台账，再在本轮排队预算（默认 120 秒）内逐个启动；
   预算用完立即返回「排队中」名单和补派指引，不再逐个等 10 分钟。
3. 有排队成员时允许补派；已在跑的专家按会话 id 跳过，不会重复拉起、不会重复烧 token。
4. 新增 `continuationPending` 交接标记：正常交接不会被误判成失败，巡检也不会
   把交接中的成员判成停滞。

### 升级方式

本机 profile 通过软链接使用本仓库（`~/.dsh/profiles/web/node_modules/dsh-workplan`），
改完源码并构建后，**手动重启 `dsh web`** 即生效；重启后在任意会话调用
`dsh_workplan_status`，版本应显示 `v3.1.8`。

### 兼容性

- 工具名、参数、返回字段保持兼容；新增 `continuation`、`queued`、`skippedRunning`
  三个字段，旧调用方忽略即可。
- 计划台账新增可选字段 `delegates[].continuationPending`（仅在交接窗口内为 true）。
- 不改变 phase-1 任务书内容，不新增模型调用。
