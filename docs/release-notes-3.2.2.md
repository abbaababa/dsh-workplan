# dsh-workplan 3.2.2

## 一句话

**不再让模型重抄/重复带同一段文字；固定格式与装配交给代码，判断与执行仍交给模型。** 基线 3.2.1，本会话修改后统一版本 3.2.2；不删除功能、不改派发/验收/交付语义。

## 改动前后一眼看懂

| 场景 | 3.2.1 | 3.2.2 | 说明 |
|---|---:|---:|---|
| 规划器复述用户原文 | 最多 8,000 字输出 | 0（平台回填） | 同一段文字不再“输入→输出→任务书”付三次 |
| 规划器对话背景（无指代） | 7,000 字 | 最近 3,000 字 | 有“它/这个/B”等指代时仍给完整 7,000 |
| 部门任务书（7,000 字对话） | 17,403 字符 | 11,593 字符 | 无指代只带最近 1,200 字；有指代保留完整背景 |
| 部门授权段 | 与简报重复约 1,300 字 | 0（真实派发带简报时） | 只有简报缺标记时才保留本地副本 |
| `delegate` 工具说明书 | 7,280 字符 | 4,121 字符 | 字段/类型/必填/枚举/错误码不变 |
| 导出工具说明书合计 | 24,061 字符 | 19,760 字符 | 按角色裁剪 + 压缩文案 |
| 结果块验收表 | 顶层 + phases 各写一遍 | 只写顶层 acceptance | 平台生成 checks/allPassed；模型写了的保留 |

## 具体改了什么

### 1. 输入 token

- 规划器不再输出 `taskUnderstanding.originalRequest`；平台从用户原文回填，上限 8,000 字，与 wire 校验同一常量。
- 规划器/部门任务书按“有没有指代”选择对话背景；无指代只带最近一段。
- 带负责人规则简报时，任务书不再重复同一份授权段；用标记 fail-open，简报不完整时自动保留本地段。
- 工具说明书压缩：`delegate`、`update`、`dispatch`、`verify` 的长解释压掉，schema 契约不变。
- 计划消息“全局任务”与用户原文锚点重复时只留一份，且只在前 4,000 字可见锚点确实包含全文时去重。

### 2. 输出 token

- 子 Agent 结果只写顶层 `acceptance`；`phases.verification.checks`/`allPassed` 由平台生成，不再要求同一张表写两遍。
- 规划器增加“输出精简”硬要求：每字符串≤200 字，简单任务的 contradictions/risks/verification/practiceLoop 各 1 条要点即可。

### 3. 一致性治本（本会话审查发现并修复）

- `MAX_ORIGINAL_REQUEST_CHARS = 8000` 单一常量，回填/校验同源；8,001 明确拒绝。
- 去重只看可见的 4,000 字锚点，避免“与上方相同”却看不到全文。
- `compactBackground` 默认关闭、真实派发开启，保留旧“完整背景不二次截断”契约。
- `recentConversation` 改为保留最新内容；参考探测失败时 fail-open 保留完整背景。
- 补回压缩简报时丢失的“少走弯路”“action=status 查看进度”两句。

## 代码/RPA 结论

- **已交给代码**：用户原文回填、验收表生成、对话窗口选择、计划消息去重、工具声明面。
- **仍保留模型**：规划器（任务分解判断）、部门/专家执行、复盘与最终综合；phase-0 复杂度自评是用户规则要求的“子 Agent 自己判断”，未用代码替代。
- 没有为了省 token 改变通知频率、派发顺序、验收门禁或并发语义。
