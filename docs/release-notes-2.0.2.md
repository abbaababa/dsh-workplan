# dsh-workplan 2.0.2 — 更正「第一、二阶段禁用插件」的适用范围

发布日期：2026-11-05（Asia/Shanghai）

## 一句话

2.0.2 只做一件事：把「第一、二阶段禁用 dsh-workplan 插件」更正为**仅适用于 2026-11-05 本次优化会话**，不再作为所有后续会话的永久产品规则。三阶段工作法、阶段三核验与自我学习复盘全部保持不变。

## 安装 / 升级

```bash
dsh plugin --profile web add dsh-workplan@2.0.2
```

装完重启一次 DSH Web（或重新载入页面）。

从 2.0.1 升级时不需要迁移数据：`phases` 证据格式、`phases.verification.retrospective`、教训记忆文件 `~/.dsh/workplan/lessons.jsonl` 都没有变化。

## 为什么要出 2.0.2

用户在 2.0.1 发布后澄清：原要求 4「第一、二阶段禁用 dsh-workplan 插件」是**本次会话内**对优化过程的约束，不是要求插件对所有未来会话禁用。1.13.0 起该条被写成了产品级规则（子 Agent 提示词、`dsh_workplan_verify` 描述、运行时报错、README 与协作文档），属于对需求范围的误读，2.0.2 全面更正。

## 改了什么

| 位置 | 2.0.1 及以前 | 2.0.2 |
|---|---|---|
| 子 Agent 提示词 | 「阶段一、二：dsh-workplan 插件禁用。不得调用任何 dsh_workplan_* 工具」 | 「阶段一、二先把问题、思路与执行记录写全；调用 verify 会因缺少前两阶段证据返回 PHASE_GATE（证据门禁，不是禁用插件）」 |
| `dsh_workplan_verify` 描述 | 「阶段一、二禁用本插件」 | 「缺少 planning / execution 证据时返回 PHASE_GATE 与待补项」 |
| 运行时报错 | 「插件在阶段一、二禁用」 | 「阶段三核验缺少前两阶段证据」 |
| README（中/英） | 声明永久禁用 | 声明仅本次会话约束；主 Agent 任何阶段都可用计划、派发、查询与改判工具 |
| 协作文档与安全文档 | 表格写「禁用」 | 写「证据门禁」并加 2.0.2 更正说明 |

## 没有变的部分

- 三阶段「规划 → 执行 → 验证」仍是产品功能；完成判定仍要求 `phases` 齐全。
- `dsh_workplan_verify` 仍只接受三阶段齐全的证据；缺 planning/execution 仍返回 `PHASE_GATE`——这是证据门禁，不是插件禁用。
- 阶段三复盘（问题 / 弯路 / 解决 / 防再犯）与永久教训记忆完全不变。
- 没有新增或删除模型工具，工具面仍是 11 个。

## 验证

- `npm run check`（tsc --noEmit）退出码 0。
- `npm test`：全量通过（具体条数见仓库发布记录与 CI 输出）。
- `tests/three-phase.test.ts` 新增断言：提示词不得再出现「插件禁用」，同时仍要求阶段三门禁与 `PHASE_GATE`。

## 兼容性

- 2.0.2 是 2.0.1 的措辞更正版，证据契约与数据格式完全兼容，可直接升级。
- 旧结果回放仍可用 `requirePhases: false` 走 1.13.0 以前的旧语义（与 2.0.1 相同）。
