# dsh-workplan 3.2.0

## 一句话

**已经登记过的东西不再让模型重抄，已经能截断的上下文不再整段重复送。** 不增加任何模型调用，不改变派发、验收、交付规则。

## 改动前后一眼看懂

| 场景 | 3.1.9 每步要付 | 3.2.0 每步要付 | 说明 |
|---|---:|---:|---|
| 部门交卷时重抄 phase-0 开工证据 | 约 2,838 字符（T4 真实样本） | 0（平台自动并入） | 省输出 token；抄薄也不会再被退回 |
| 依赖结果摘要 | 最多 1,200 字/条 | 最多 800 字/条 | 完整原文在产物/会话里，仍可读 |
| 兄弟部门简报 | 每条摘要 200 字，整块 2,000 字 | 每条 80 字，整块 1,500 字 | 目标/产物也各压到 60/80 字 |
| 历史教训 | 最多 8 条 / 3,200 字 | 最多 6 条 / 2,200 字，同主题去重 | 同一规则不再因多条近似记忆付多遍 |
| 全局任务 + 用户锚点 | 同一段话常常出现两遍 | 重复时只留锚点一份 | 约省 500–1,200 字/任务书 |
| phase-1 结算模板 | 992 字（含 planning/preparation 示例） | 541 字（只留 execution/verification） | 配合「免重抄」 |
| 给主 Agent 的可见正文 | 无上限 | ≤600 字，细节放产物/证据块 | 防止正文、departmentSummary、证据块三份重复 |

## 具体改了什么

### 1. 交卷免重抄开工证据（最大的一块输出节省）

phase-0 已经把第 1/2/3 步（planning + preparation）登记为 durable 事实。3.1.9 仍要求每个部门交卷时逐字重抄，T4 真实样本里这部分占 phases 的 45%。3.2.0 起：

- 交卷只写 `execution`（怎么做的）与 `verification`（怎么验证的），以及顶层 `acceptance / artifacts / report`；
- `planning / preparation` 缺哪个清单，平台就用登记原文补哪个；
- 交卷自己写了的清单原样保留，平台再做并集落账；
- 结算校验、`dsh_workplan_verify`、沟通格式 F3 三处同一口径；
- 没有登记证据的旧计划仍要求四组齐全，不会误放行。

### 2. 任务书瘦身

- 依赖摘要去掉证据块后压到 800 字、最多 5 个产物引用；
- 兄弟简报只保留「谁、什么状态、目标 60 字、产物 80 字、完成摘要 80 字」；
- 历史教训按「预防硬规则前 30 字」去重，只留最高相关的 6 条、总计 2,200 字；
- 全局任务与用户原要求锚点重复时，只保留锚点这一份；
- phase-1 结算模板去掉 planning/preparation 示例，减少示例本身占用的输入。

### 3. 正文限长

每个部门给主 Agent 的可见正文要求 ≤600 字，细节写进产物和结构化证据块。主 Agent 需要的是「关键结论 + 证据在哪」，不是第二份完整报告。

### 4. 把五处互相矛盾的口径统一

旧版有五个地方分别暗示「必须重抄」或「缺 planning 就退回」；现在统一为：

- **有 phase-0 登记**：planning/preparation 可省略，平台自动并入；
- **无登记（旧计划/旧回放）**：四组证据仍须齐全；
- **只写半组 planning**：按字段补齐，不会因空对象或半组内容误退；
- **平台并入的登记证据**：不再计入 6000 字交卷上限，避免「省输出」制造新退回。

## 没有改什么（避免误解）

- 不改任务怎么拆、怎么派、怎么验收、怎么交付；
- 不改工具权限、并发、重试、超时、结算备份机制；
- 不新增模型调用；
- 不改旧会话的回放语义：没有登记证据的历史行仍按旧规则判定。

## 怎么确认生效

1. 重新加载插件（重启 DSH，或在插件管理里禁用再启用）；插件不会自行重启。
2. 新会话里调用 `dsh_workplan_status`，返回版本应为 `v3.2.0`。
3. 源码验证：`npx tsc -p tsconfig.json --noEmit` 通过；`npm test` 应为 **1440 通过 / 0 失败 / 1 todo**。
4. 真实任务里看两处：部门交卷的结果块可以只有 `execution / verification`；给主 Agent 的正文明显短于旧版。
