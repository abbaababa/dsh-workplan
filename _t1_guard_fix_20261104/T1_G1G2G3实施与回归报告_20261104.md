## 五、修复后新增的回归用例（双向有效）

   - 反向保护：未交付的其它路径对子 Agent 仍放行。
2. **G2**：`G2 已修复：第四个写类工具名按参数形状进闸门，读类调用不受影响`
   - apply_patch / write_file / create / some_future_editor 全部被拦。

3. **G3**：`G3 反向：交付链接路径、改写真实路径同样被拦；不同文件不被误伤`
   - 正向：present 真实路径、写链接路径 → 拦。

## 六、过程中发现并修掉的真问题（不是「跑绿了就算」）

1. **G2 第一次实现漏判**：最初要求「路径参数 + 内容参数同时存在」，导致真实 write 调用被放过
   （测试红：`✖ ... actual: 'undefined', expected: 'string'`）。根因是判定过窄。
   修正为「读类工具显式排除 + 路径参数存在即为写」，语义更准也更简。
2. **G2 误伤读工具**：`read` 也带 `file_path`，一度被当成写操作拦下。
   修正：引入 `READ_ONLY_TOOLS` 显式白名单，读类永不进闸门。
3. **G3 反向漏判**：presented 条目缓存里存的是旧 canonical，与真实身份不能逐字比较。
   修正：缓存改存 `identityPath`，并在比对时对 `entry.raw` 现场重算真实身份。
4. **build 陷阱**：`npm run build` 只复制 `dist/*.js` 到 `lib/`；若跳过 build 直接跑旧 lib，
   会读到旧代码而误判「改了没效果」。教训：改完 src 必须先 `npm run build` 再验证。
